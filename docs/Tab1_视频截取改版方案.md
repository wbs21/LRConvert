# Tab1「视频截取」改版方案（目标版本 4.1）

> 本文档由需求沟通整理，用于开工前最终确认。
> 标注 **【待确认】** 的条目给出的是建议默认值，未回复即按默认值实施。

## 0. 目标与不做什么

- 目标：把 Tab1 从「两个时间输入框 + 开始/停止」改造成**可视化时间轴剪辑界面**：
  缩略图 + 波形 + 刻度 + 视窗滑块 + 可拖动起终点标尺 + 当前帧预览。
- **仍然不重新编码**：保持流拷贝、快、无损、不改分辨率（这是本 Tab 的定位）。
- 不改动其他 Tab；不引入 Qt Multimedia（解码复用自有 `FfmpegApi`）。

## 2. 影片显示区（核心控件）

一个自定义 QWidget，纵向分 4 层，**共享同一套时间↔像素映射**（`visibleStart / visibleEnd`）：

```
┌──────────────────────────────────────────────┐
│ ① 缩略图层    5 张：可视区间 左/1/4/中/3/4/右     │ ← 绿/红标尺手柄在最顶端
├──────────────────────────────────────────────┤
│ ② 波形层      灰色，可见区间切 600 片，片内按该片高度填满 │
├──────────────────────────────────────────────┤
│ ③ 时间码层    大刻度（带时间文字）+ 小刻度（画线） │
├──────────────────────────────────────────────┤
│ ④ 滑块层      浅蓝底条（全片，不可拖）           │
│               深蓝滑块（可视区间，可拖动平移）    │
└──────────────────────────────────────────────┘
         ↑ ①②③ 区域之上叠三条竖向标尺（见 §3）
```

### 2.1 缩略图层

- 显示 **5 张图**：可视区间的 **左 / 1/4 / 中 / 3/4 / 右** 五个时间点各取一帧
  （末点取 99.9% 而不是 100%，避免 seek 到正好等于片长时取不到帧）。
- **高度贴合影片条高度**，宽度按原比例走，装不满的地方**左右留空隙**——
  不拉伸、不裁切（早期版本是"铺满再裁掉溢出"，会把画面切掉）。
- 视频刚导入时**默认全长充满**（缩放 = 适应全长）。
- 缩放/平移**停止后**由后台线程重新解码这 5 帧并刷新（拖动过程中不重解码，先沿用旧图）。

### 2.2 波形层

- **音频波形**，灰色填充柱（中心轴对称），与底色有对比即可。
- **整轨全量 + 分段并行**（2026-10-14 改定稿，取代原来的"只算可见区间"）：
  1. 导入后立刻按固定密度给**整条音轨**开一条峰值数组（400 点/秒，>2 小时降到 100）；
  2. 把整轨切成 **16 段**，**4 个 worker 线程**各领一段并行算（可见区所在段优先）；
  3. **每算完一段就重绘一次** —— 波形一段一段填出来，不用等全部算完；
  4. 屏幕侧再按控件宽度切片（每 2 像素一片，最多 600 片），片内取该区间的峰值填满。
- **缩放 / 平移 / 播放都不再重算波形**：数据是全量的，视窗变了只要告诉后台
  "现在看的是哪一段"（重排剩下没派发的段的优先级）即可。
- **「没算」和「算出来是静音」必须分开**：每片有一个 `ready` 标记，没算到的片
  **留白**，不能画成 0 高度 —— 否则整段波形看着像没声音。
- 只有整轨数组还没建立时（导入最初一瞬）才画中线 + 灰字「波形计算中…」
  （无音轨则显示「无音轨」）。

### 2.3 时间码层

- 刻度密度**随缩放自适应**：可见区间长 → 稀疏，放大 → 自动变密（两级：大刻度带时间文字、小刻度只画线）。
- 标签建议格式 `00:00:02.500`（保留毫秒）。【待确认】

### 2.4 滑块层（总览 + 视窗）

| 条 | 含义 | 行为 |
|---|---|---|
| 浅蓝底条 | 全片长度，横向充满 | 仅作轨道，不可拖动 |
| 深蓝滑块 | 当前可视区间在全片中的位置与占比 | **可拖动**平移；宽度 = 可视区间占全长比例 |

- 缩放到全长时滑块满宽、拖动无意义 → 自动禁用。
- **拖动中的刷新策略**：先用缓存低精度绘制（波形聚合、缩略图沿用旧图）保证跟手，
  **松手后**触发一次精修重绘（重取 3 张缩略图、补齐该区间波形精度）。
- 【待确认】点击浅蓝底条某处直接跳转（建议：加）。
- 【待确认】深蓝滑块两端可拉伸缩放（建议：不做，只平移）。
- 【待确认】在浅蓝底条上用绿/红小刻度标出起点/终点在全片的位置（建议：加）。

## 4. 预览窗与执行按钮

- **预览窗**显示蓝色标尺（当前帧）位置的画面，拖动标尺时实时刷新（节流约 50ms），松手后精确 seek。
- 预览窗右侧是一列「**目前时长** + 数值 + 开始剪辑按钮」，三者在一个 `QVBoxLayout`
  （`verticalLayout_T1action`）里顶部对齐，末尾加垂直 spacer 把整列顶上去。
- **单一切换按钮**取代现状的「开始截取」+「停止编码」两个按钮：
  - 常态：**蓝色 `#1565C0`**、文字「开始剪辑」；
  - 执行中：**变红 `#D32F2F`**、文字「停止编码」（再点即停止）；
  - 完成/停止后恢复蓝色。
- 三个按钮统一配色（与起终点标尺配色一致）：
  | 按钮 | 常态色 |
  | --- | --- |
  | 设为起点 `T1setStart` | 绿 `#2E7D32` |
  | 设为终点 `T1setEnd` | 红 `#D32F2F` |
  | 开始剪辑 `T1start` | 蓝 `#1565C0` |
  - 每个按钮的样式都带 `:hover` / `:pressed` / `:disabled` 分支；
    置灰态用 `#E0E0E0` 底 + `#9E9E9E` 字，避免"按钮上了色却看不出能不能点"。
- **目前时长** `T1duration`：`终点 - 起点`，跟着标尺/时间码/吸附实时更新，
  由 `MainWindow::syncCutTimeEdits()` 统一刷新（起点、终点、时长三处一起改）；
  导入新文件时先归零。
- 执行期间：文件选择、时间码输入、时间轴交互一律置灰（与现有 `setBusy()` 一致）。

> **实现要点**：按钮的常态样式写在 `mainui.ui` 里，执行期要临时换成红色，
> 所以 `setupTimeline()` 里先把 `T1start->styleSheet()` 存进 `cutStartStyle_`，
> `setBusy(false)` 时用它还原 —— 颜色只在 `.ui` 里写一份，不会两边漂移。

## 4.1 预览播放条（播放 / 停止）

预览窗右侧那一列，从上到下是：**播放按钮 → 目前时长 → 数值 → 开始剪辑**。

- **只有一个按钮**，在「▶ 播放」与「■ 停止」之间切换（原计划的快进/快退已按需求取消）：
  - 常态：绿 `#2E7D32`，文字「▶ 播放」；
  - 播放中：红 `#D32F2F`，文字「■ 停止」。
- **空格键等同这个按钮**。只在 Tab1 生效，且焦点在输入框（文件名、时间码）时空格仍然是打字。
- **从当前帧（蓝色标尺所在位置）开始播**，播到片尾自动停。已经在片尾时点播放会从头播
  （否则一点就立刻结束，看着像按钮坏了）。
- 播放时蓝色标尺跟着往前走，画面同步刷新；**停止后停在最后一帧**，不回退。
- 编码任务执行期间播放按钮置灰（不跟编码抢 CPU）。

### 实现要点

- 播放引擎 `src/player/FramePlayer`：常驻 `std::thread`，**seek 一次 + 顺序解码**。
  不能每帧都 seek —— 那是"从关键帧重新解一整个 GOP"，会卡成幻灯片。
- 它**自己开一份文件句柄**，不与拖标尺取单帧的 `cutGrabber_` 共用 `AVFormatContext`：
  `av_read_frame` 是"读走一个包"，两个消费者共用一个句柄会互相偷对方的包。
- 取帧器为播放补了 `seekTo()` / `grabNext()`（原来只有 `grabAt()`，每帧都 seek）。
- 播放中**抑制** `refreshCutPreview()`：画面由播放线程逐帧送来，再取一次只会抢解码器。

### 声音

- 音频链路：音轨 → `AudioDecoder`（解成 48kHz/立体声/s16）→ `AudioOutput` → 声卡。
- **没用 Qt Multimedia 的 QAudioSink**：它会在发布包里带一份 Qt 自己的 FFmpeg 后端
  （几十 MB），与§8「不引入 Qt Multimedia」冲突。改用 **Windows waveOut**（`winmm.dll`
  系统自带，零部署成本，只需 `target_link_libraries(... winmm)`）。
- 音画同步只认视频时钟；音频是"尽力喂"，声卡堵了就丢，**绝不卡住播放循环**。
- 只有 1 倍速播放才出声（倍速/倒放已取消，不存在变速变调的问题）。
  文件没有音轨时照常播画面，日志提示「无音轨，只有画面」。

### 播放时的「翻页」（2026-10-14 由「页面滚动」改过来）

用户原话：

> 播放时，放弃滚动模式，改为翻页，播放指针从左向右走，到达右端后，影片向左跳，
> 让当前帧回到最左端，相当于翻页。

**页内不动视窗**，播放头（蓝标尺）自己从左往右走；**走到右端才整页向左跳**，
跳完播放头出现在新页的**最左端**。片尾处钳住（`duration - s`），
播放头在最后一页里继续往右走到片子结束。

```cpp
// TimelineWidget::pageViewForCursor()
const bool inside = cursor_ >= viewFrom_ && cursor_ < viewTo_ - 1e-6;
if (inside) return;                                   // 页内：什么都不做
const double from = clamp(cursor_, 0.0, duration_ - s); // 新页左端 = 当前帧
if (std::abs(from - viewFrom_) < 1e-6) return;        // 已经在这一页
viewFrom_ = from; viewTo_ = from + s;
```

和旧「滚动」的分水岭就一行：滚动是 `from = cursor - s/2`（**每帧**都把播放头摆回
中间），翻页是**只在页外才动**。

| 播放头位置 | 视窗 | 效果 |
|---|---|---|
| 页内 | **纹丝不动** | 播放头从左往右走 |
| 走到右端 | 整页左跳 `from = cursor` | **播放头回到新页最左端** |
| 最后一页（片尾） | 钳在 duration−s ~ duration | 不再翻页，播放头走到片子结束 |

播放线程每帧回调里跟着 `setCursorSec()` 一起调（见下条"回环"）。
**只在真正翻页的那一帧**改视窗并发 `viewChanged` —— 每帧都发的话上层会不停地
重算波形和缩略图，而且那就又变回滚动了。

### 播放中改动当前帧 = 停 → 定位 → 立刻重播

播放时点/拖时间轴上别的位置，按用户指定的思路走三步（中间有一次短暂停顿，
**用户明确表示可以接受**）：

1. `cursorChanged` 一到就 `stopPlayback()`，并立起 `playInterruptedByUser_`；
2. 标尺已经被时间轴自己挪到点击处；
3. `cursorSettled`（松手）时看到 `playInterruptedByUser_`，立刻 `startPlayback()`
   从新的当前帧播。

先试过"播放中 seek"（`FramePlayer::seekTo()` 登记请求、播放线程里做 seek），
**实测无效**：播放线程每帧都在把标尺改回播放位置，用户点的那一下会被立刻覆盖，
看着像"点了没反应"。所以改成了现在这条"干脆停一下再起"的路子，
`FramePlayer::seekTo()` 与 `seekRequest_` 已删除，`AudioOutput::reset()` 随之删除。

配套细节：

- `playUpdatingCursor_` 标志用来区分"用户拖的"和"播放自己推进的"：
  播放线程更新标尺时先立起这个标志，否则它触发的 `cursorChanged` 会被当成
  用户操作又去停一次，播放就会自己追自己、抖成一团；
- 被打断的那次 `stopPlayback()` **跳过** `scheduleTimelineAssets()` /
  `schedulePreview()` —— 马上就要重播了，补波形/补单帧只是白占 CPU，
  还会让重播卡一下。

### 踩坑：旧播放线程迟到的"播完了"会把重播状态清掉

`player_.stop()` 要 join 播放线程，线程退出时那条 `endCb_`（排队的
`onPlaybackEnded`）**可能晚一步才到 GUI 线程**：此时新一轮播放已经起来了，
它一看 `playRunning_ == true` 就照章办事置成 false —— 按钮跳回「▶ 播放」，
帧回调里的 `if (!playRunning_) return` 从此把每一帧都丢掉，
标尺和视窗停在原地不动（冒烟实测：点了 4.9s 之后标尺一直是 4.900、视窗一直是
1.3~3.3，但播放位置照常推进到 5.533，非常迷惑）。

两道保险：

- `FramePlayer` 加 `silentStop_`：主动 `stop()` 的那次不回调 `endCb_`
  （UI 是自己按下停止的，它已经知道停了，不需要通知）；
- `MainWindow` 加 `playEpoch_` 世代号：`startPlayback()` 时 +1，`endCb` 捕获
  当时的值，对不上当前世代就直接丢掉。

### 踩坑：seek 只能落在关键帧上，开头几帧会早于起点

本片关键帧间隔 1 秒，从 5.9s 起播时 seek 落在 5.0s 的关键帧，顺序解码的第一帧是
**5.0s** —— 画面会先往回退一大截再往下播（冒烟里实测退到了 5.333s）。
修法：播放线程记下 `playFrom_`，凡 `actualSec < playFrom_` 的帧直接丢掉。

### 播放中拖动底部滑块 = 停止播放

播放时用户只要动了底部滑块层（拖深蓝滑块 / 点底条跳转 / 滚轮缩放），**立刻停播**。
理由很实在：播放每帧都在 `pageViewForCursor()` 里重设视窗，不停的话用户刚拖到的
位置下一帧就被覆盖回去，滑块会"自己弹回来"。

实现上不能复用 `viewChanged` —— 那个信号播放翻页时控件**自己也会发**，
照它停播等于播到每一页边界就自己停。所以另开一个信号：

```cpp
void viewDraggedByUser();   // 只有人手身在滑块层上才发
```

发出点只有三处：`panViewTo()`（拖动中，每个 mouseMove 都会发一次，上层幂等无事）、
滑块上的 `mousePressEvent`（手落下去意图就明确了，不必等第一次移动）、
`wheelEvent()`（滚轮缩放同属用户在改视窗）。
`pageViewForCursor()` / `setViewRange()` 是程序改的，**不发**它。

上层只接一句：

```cpp
connect(timeline_, &TimelineWidget::viewDraggedByUser, this, [this]() {
    if (playRunning_) stopPlayback();
});
```

注意拖滑块只停止、**不重播**（和上面"改当前帧"那条不一样）：
用户拖滑块是想看别处的画面，没让他松手后继续播的道理。

### 空格键为什么用全局 eventFilter 而不是 keyPressEvent

只重写 `keyPressEvent` 不够：点过「开始剪辑」之后焦点会留在那个按钮上，
Qt 的 QPushButton 本身就会吃掉空格（当成"按下我"），一按空格就直接开始编码了。
所以把过滤器装在 `qApp` 上，Tab1 下除了输入框之外空格一律归播放，并**吞掉事件**。
窗口析构时必须 `qApp->removeEventFilter(this)`，否则退出时会回调到已析构的对象。

冒烟（`LRCONVERT_CUT_FILE=test/fix720.mp4`，6s 片长；7.0s 把可见区收窄到 0~2s 后播放）：

```
播放前：                    播放中=否 标尺=00:00:00.000 视窗=00:00:00.000~00:00:02.000
播放 1s（页内）：            播放中=是 标尺=00:00:00.900 视窗=00:00:00.000~00:00:02.000  ← 视窗纹丝不动
播放 2.1s（已翻页）：        播放中=是 标尺=00:00:02.100 视窗=00:00:02.000~00:00:04.000  ← 整页左跳，播放头在最左端
```

## 5. 剪辑行为

- **流拷贝、不重新编码、不改变分辨率** —— 仍走 `RemuxTask` 的 `CopyAll` 路径。
- **关键帧吸附规则**（按需求原文）：
  - 起点 → 吸附**选取点右侧**最近关键帧；
  - 终点 → 吸附**选取点左侧**最近关键帧；
  - 即输出始终是所选区间的子集（两边都往里缩）。
- **吸附结果回显**（建议）：设定/拖动结束后，标尺吸附到真实关键帧位置、时间码框更新为吸附后的实际值，
  日志输出一行说明（如「起点 2.000 → 吸附到 2.400」）。
- 关键帧表：导入后用 `av_read_frame` 扫一遍包头（**不解包内容**，很快）取得关键帧时间戳列表，供吸附与刻度参考。
- 输出命名沿用现状（`pathutil::outputPath` + `copySafeSuffix`）。
- 边界处理：
  - 起点/终点钳制在 `[0, 片长]`；
  - 吸附后起点 ≥ 终点（选区太短、区间内无关键帧）→ 提示并不执行。

### 界面固定提示文案（区域 6）

> 视频截取功能为快速拷贝，不重新编码，不改变原视频分辨率。起点将吸附选取点右侧最近关键帧，终点将吸附选取点左侧最近关键帧。

### 过程中踩到的坑

1. **seek 后清解码器必须用 `avcodec_flush_buffers`（已加入符号表）。**
   用"发一个空包 `avcodec_send_packet(ctx, nullptr)`"代替是错的：空包是流结束语义，
   会把解码器推进 draining 状态，之后所有 send_packet 都返回 `AVERROR_EOF`
   （-541478725），表现为"取不出任何画面"。
2. **读 `fmt->duration` 前必须先 `avformat_find_stream_info`。** 否则 MP4 上常常是 0，
   波形分桶数算成 0，表现为"没有波形"。

## 8. 技术实现要点

- **不引入 Qt Multimedia**：预览帧与缩略图一律用自有 `FfmpegApi` 解码（无额外部署体积、与转码管线一致）。
- 全部解码/探测工作放**后台线程**（沿用现有 `startAsyncInit` 的异步思路 + `QtConcurrent`），UI 线程只做绘制。
- 建议新增文件：
  - `src/ui/TimelineWidget.h/.cpp` —— §2 复合控件（4 层绘制 + 3 条标尺 + 缩放平移交互）
  - `src/core/MediaProbe.h/.cpp` —— 媒体信息（§1-5）、关键帧表、音频峰值缓存
  - `src/ffmpeg/FrameDecoder.h/.cpp` —— 取指定时间戳的一帧（seek + 解码 + 转 QImage）
- 音频解码取峰值复用现有 `FfmpegApi` 的 avcodec/avformat/swresample 符号。
