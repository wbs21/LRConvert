# 窗口外观与几何（程序名 / 图标 / 最大化还原位置）

> 记录主窗口"长得叫什么、长什么样、放在哪"这一类改动与结论。
> 与之相关的历史 bug：BUG-001（最大化还原后标题栏跑出屏幕，2026-10-15 修）。

---

## 1. 程序名

`Little Rabbit Convert` → **`LRconvert`**，窗口标题格式 **`LRconvert v<版本>`**（版本单一来源 `src/core/Version.h`，当前 v4.0.1）。

统一在三处，缺一个就会出现"设计器里看到的和跑起来看到的不一样"：

| 位置 | 内容 |
| --- | --- |
| `src/MainWindow.cpp` `kAppName` | 窗口标题的前半段（+ `" v"` + 版本号） |
| `src/main.cpp` `setApplicationName()` | QApplication 级名字（工程里没用 QSettings，改它无副作用） |
| `src/ui/mainui.ui` `windowTitle` | 设计器/预览用的初值，运行时会被上面那句覆盖，但要保持一致 |

`python/` 下是旧 Python 版源码、历史文档里的旧名字，属于存档，没动。

## 2. 图标（`LRconvert.ico`，放仓库根目录）

图标这件事要分两层做，Qt 的 `setWindowIcon()` 只管得了其中一层：

| 层 | 做法 | 管什么 |
| --- | --- | --- |
| **exe 本体** | `resources/app.rc`（`IDI_ICON1 ICON "../LRconvert.ico"`） | 资源管理器里的文件图标、没显式设图标的窗口（QMessageBox 等）、任务栏回退 |
| **运行时窗口** | `resources/app.qrc` + `setWindowIcon(":/LRconvert.ico")` + `app.setWindowIcon()` | 标题栏图标、任务栏图标 |

CMake 侧两件事：

```cmake
if(WIN32)
    enable_language(RC)                                    # 让 .rc 被 windres 编译
    target_sources(LRConvert PRIVATE .../resources/app.rc)  # 只在 Windows 上加
endif()
set(CMAKE_AUTORCC ON)   # ← 关键，见下
```

### ⚠️ AUTORCC 从来没开过（图标"莫名其妙没有"的真凶）

`qt_standard_project_setup()` **只开 AUTOMOC / AUTOUIC，不开 AUTORCC**。
于是 `.qrc` 一直没被编译进 exe（`build/` 里搜不到任何 `qrc_*.cpp`），
`QIcon(":/xxx")` 恒为空，**而且不报任何错** —— 排查时极易被忽略。

判据：构建日志里必须出现

```
Automatic RCC for resources/app.qrc
Building CXX object ... qrc_app.cpp.obj
```

冒烟里加了自检（`[SMOKE] 窗口图标：N 个尺寸`），空图标会直接打印「空！」。

## 3. BUG-001　最大化后还原，标题栏跑到屏幕上方

- **状态**：✅ 已修（2026-10-15）；用户 2026-10-14 报
- **现象**：点最大化再点还原后，标题栏被屏幕顶部裁掉、窗口抓不住拖不动，
  只能靠拖边框把尺寸改一下才会跳回可见位置。

### 取到的实测数据（冒烟自动跑，不用人工点标题栏）

新加了三个冒烟钩子：`smokeSetMaximized()` / `smokeWindowGeom()` /
`smokeNudgeOffScreen()`，脚本自己完成"拖到顶 → 最大化 → 还原 → 人为顶出屏幕"，
把 `geometry / frameGeometry / normalGeometry / minimumSizeHint / availableGeometry`
全打出来。1920×1080、可用区 1032、缩放 100% 下：

```
拖到顶部：    客户区=560,31   800x639  外框=560,0    800x670  最小高=639
最大化中：    客户区=0,23    1920x1009 外框=0,-8    1920x1040  ← 外框顶到 -8
还原后：      客户区=560,218  800x639  外框=560,187  800x670   ← 本机不复现
```

两个结论：

1. **最大化态外框 y = -8** —— Windows 会故意把可拖拽的边框推到屏幕外 8px。
   这就是污染源：一旦这 -8 被当成正常几何带回来，标题栏（约 31px）就基本全在屏幕外了。
   本机 Qt 6.12 的 `normalGeometry()` 没被污染，**所以脚本化还原没能复现**，
   用户的机器（不同缩放/屏幕高度）才有。
2. **`.ui` 写的 596 与布局真实最小高度 639 差 43px** —— 窗口会在首帧显示之后
   被撑大，`normalGeometry` 与真实几何从一开始就对不上。这是最可疑的放大器。

### 修法（两条都做了）

**B（治本）**：`src/ui/mainui.ui` 的 `geometry` 高度 596 → **640**，
与实测 `minimumSizeHint().height() = 639` 对齐。窗口初始几何即最终几何，
不再有"首帧后被撑大"这一段不一致。

**A（兜底）**：覆写 `changeEvent`，只在"从最大化/全屏回到正常态"时，延后 100ms
调用 `keepWindowOnScreen()` —— 把外框按回屏幕可用区（顶部/左侧不越界、
宽高不超过可用区）。延后是必要的：还原那一刻 Windows 还在发 WM_MOVE/WM_SIZE、
布局还在重排，此刻的几何是中间态。

### ⚠️ 不能信 `QWidget::frameGeometry()`

第一版兜底就是栽在这里：窗口被挪到屏幕外时，Qt 算出来的外框**退化成和客户区
一样**（边框偏移被当成 0）。表现非常迷惑 —— 修正"生效"了，窗口确实动了，
但只被挪到客户区 y=0，外框还在 -31，标题栏照样看不见：

```
修正前：  客户区=560,-9  外框=560,-40    ← 此时 dy 算出来还是对的（-31）
修正后：  客户区=560,0   外框=560,-31    ← 执行时 dy 变成 0，于是只挪到 y=0
```

所以新增 `src/platform/WindowFrame.{h,cpp}`：Windows 上直接
`GetWindowRect()` 拿外框 + `ClientToScreen()` 拿客户区原点，
两者相减得真实边框偏移，再按 `devicePixelRatioF()` 换算回逻辑像素；
拿不到才回退到 Qt 的 `frameGeometry()`。

修好后的冒烟（人为把窗口顶出屏幕再修）：

```
已顶出（修正前）：  客户区=560,-9  外框=560,-40
顶出屏幕后拉回：    客户区=560,31  外框=560,0    ← 标题栏完全回到可见区
```

冒烟序列里这几步一直在跑（4.5s~5.8s，排在播放冒烟之前），以后再犯会被直接打出来。
