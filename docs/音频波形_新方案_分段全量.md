# 音频波形计算 —— 新方案（分段全量 + 4 线程 + 边算边画）

> **状态**：✅ **已实现并验证通过**（用户 2026-10-14 提出，同日开工完成）。
> 落地结果与实测数据见 §8。
>
> 旧方案（只算可见区间 600 片）已存档在 `docs/音频波形计算方法_存档.md`
> + `docs/archive/waveform-2026-10-14/`，**新方案不理想可原样回滚**（该文档 §8 有三步回滚步骤）。
>
> 本文写的时候**没有改动任何 `src/` 代码**。

---

## 1. 用户原话

> 新的音频波形绘制方法，我想改为：先导入视频，然后开始分 4 线程分段全量计算波形，
> 边计算边绘制。优先计算可见区域内的波形。

拆成四条硬性要求：

1. **导入即启动**，不用等用户缩放/平移才去算；
2. **全量计算**整条音轨（不是只算可见区间）；
3. **4 个线程分段**并行；
4. **边算边画**，且**可见区域优先**。

---

## 2. 与旧方案的差别（一句话）

| | 旧方案 | 新方案 |
| --- | --- | --- |
| 算多少 | 只算**当前可见区间** | **整条音轨**全量 |
| 什么时候算 | 导入后算一次，**每次缩放/平移重算** | 导入后算一次，**之后不再重算** |
| 线程 | 1 个后台任务（`QtConcurrent::run`） | **4 个 worker** 分段并行 |
| 出图节奏 | 整段算完才刷新 | **每算完一段就重绘**（渐进式填充） |
| 优先级 | 无（就一个区间） | **可见区间所在段优先** |
| 片数 | 固定 600 片 | 固定密度（点/秒），见 §3 |

收益很直接：**缩放、平移、播放时都不再重算波形**，界面不会再因为这些操作卡一下；
代价是导入后要多花一点 CPU/IO，长视频尤其。

## 3. 开工前必须先定的参数（待用户拍板或先按建议值做）

| 项 | 建议值 | 理由 / 备选 |
| --- | --- | --- |
| 峰值密度 `pointsPerSec` | **400** | 波形层最宽约 1200px；放大到 3 秒窗口时 400/s 仍能给出 1200 点，够细腻。1 小时片 = 144 万点 × 2 × 2B ≈ **5.8MB** |
| 超长片降密度 | > 2 小时自动降到 **100 点/秒** | 10 小时片 400/s 要 57MB，降到 100/s 是 14MB |
| 分段粒度 | **段数 = 16**（多于线程数，便于优先级调度） | 每段独立 seek + 解码；段太短则 seek 开销占比高 |
| worker 线程数 | **4**（用户指定） | 机械硬盘上 4 线程可能反而更慢，可留成常量方便调 |
| 段内 seek 回退 | **沿用 1 秒** | 旧方案验证过（音频 seek 落点不精确，不退会缺一块） |

密度也可以在算完之后按可见区间做**降采样显示**：`peakLevel()` 已经是"取区间内最大值"，
全量数据比屏幕片数多时它天然就做了这件事，不用额外改。

## 4. 结构草案

### 4.1 数据：一整条，预先分配好

```
整轨 AudioPeaks
  fromSec = 0, toSec = duration
  pointsPerSec = 400（或降档值）
  min[] / max[]  长度 = ceil(duration * pointsPerSec)，一次性 resize 好
```

**关键**：数组先 `resize()` 到位、之后**不再改变大小**，4 个线程各自写**互不重叠的下标区间**，
这样并发写 `std::vector<int16_t>` 的不同元素是安全的（不同元素是不同的内存对象，
且不会 realloc）。比"每段算完再合并"省一次拷贝，也天然支持边算边画。

未算到的片保持初始值 0 —— 绘制时按"空洞"处理（见 §4.4）。

### 4.2 任务队列 + 4 个 worker

```
WaveformJob { int segIndex; double t0, t1; }
队列按优先级排序：
  ① 与当前可见区间 [viewFrom, viewTo] 相交的段排最前
  ② 同在可见区内，按段中点离"可见区中心"的距离升序
  ③ 其余段按时间顺序
```

- 4 个 worker 循环取队首任务 → 各自 `avformat_open_input` 一份（**每个线程独立的文件句柄和
  解码器**，`av_read_frame` 是"读走一个包"，不能共用 `AVFormatContext`）→ seek 到 `t0 - 1s`
  → `avcodec_flush_buffers` → 解到 `t1` 停 → 写进大数组对应区间 → 通知 GUI 重绘。
- **可见区间变化时重排剩余队列**（`onCutViewChanged` 里触发一次重排），
  已经派发的那 4 个不打断，做完再说。
- 换文件：`cutToken_` 自增，队列清空 + worker 收到停止标志退出（并入现有 `stopAll_` 机制）。

### 4.3 复用旧代码的地方

`AudioPeaks.cpp` 里的 `buildCore()` 已经是"解 [from,to) 并投片"的完整实现，
**新方案不要重写它**，改成：

- 抽出一个 `buildSegment(api, path, segT0, segT1, 全局数组 + 偏移, error)`；
- 复用里面的：8kHz/单声道/s16 重采样、seek 回退 1 秒、`avcodec_flush_buffers`、
  投片 `feed`、冲 swr 残留 —— 这五处全是踩过坑的，原样搬。

### 4.4 绘制：空洞与渐进

- 每完成一段 → `QMetaObject::invokeMethod` 回 GUI → `timeline_->update()`（只重绘，不重算）。
- `drawWaveform()` 要能区分两种"空"：
  - **还没算到**（空洞）→ 什么都不画（或极淡的占位），**不能画成 0 高度**，否则看着像静音；
  - **算到了但确实是静音** → 只画中线那一点。
  - 做法：给 `AudioPeaks` 加一个"已完成区间"的记录（比如 `std::vector<std::atomic<bool>> done`
    或几个"已完成到哪"的水位线），`peakLevel()` 遇到未完成区间返回 -1 表示空洞。
- 全量算完后，`peaksCoverView()` 恒真，"波形计算中…"占位只在最初几帧出现。

### 4.5 随之可以删掉的东西

- `MainWindow::rebuildCutWaveform()` 里的"按可见区间重算"逻辑：
  只在**无音轨**或**全量任务失败**时兜底用；
- `onCutViewChanged` / `refreshCutTimelineAssets` 里的波形部分（缩略图还要留着）；
- 播放结束 `stopPlayback()` 里的 `scheduleTimelineAssets()` 不再需要为波形补算（缩略图仍要）。

## 6. 风险与待观察

- **4 线程同解一个文件**：CPU 是多核就赚了；机械硬盘上随机 seek 可能反而变慢 ——
  实测一下导入耗时（拿 1~2 小时的长片试），不行就降到 2 线程或改"顺序读 + 单线程解、
  多线程只做后处理"。
- **内存**：见 §3，超长片靠降密度兜住。
- **导入瞬间 CPU 打满**：可能影响首帧预览的取帧，必要时把 worker 的优先级调低
  （`QThread::LowPriority` 或让首帧取帧先跑完再启动）。
- **段边界**：相邻段各退 1 秒，会重复解一点、`t0` 之前的部分照旧丢弃（现有 `feed` 已处理），
  但要确认接缝处不出现"错一小格"。

## 8. 落地结果（2026-10-14）

按 §3 的建议值实施：密度 400 点/秒（>2 小时降到 100）、16 段、4 worker。

**改了什么**

- `AudioPeaks`：新增 `allocate()`（一次性开好，之后不改大小）、`ready[]` 水位线、
  `indexAt()`；解码骨架抽成 `AudioPeakBuilder::decodeRange()`（投片交给回调 `SampleSink`），
  `build` / `buildRange` / `WaveformBuilder` 三处共用，那五个坑只写了一遍；
  `level(i)` 未算返回 **-1**（空洞）。
- 新增 `src/ffmpeg/WaveformBuilder.{h,cpp}`：16 段 + 4 worker + 优先级队列
  （页内按离可见区中心的距离、页外排后面）+ `stop()` 可中断。
- `TimelineWidget`：`peaks_` 改成 `std::shared_ptr<const AudioPeaks>`（**共享不拷贝**，
  一小时片子好几 MB，每算完一段拷一次太贵）；`peakLevel()` 跳过空洞；
  屏幕片数按控件宽度定（每 2 像素一片，上限 600）。
- `MainWindow`：`startFullWaveform()` 启动全量任务；`onCutViewChanged` 只
  `setPriorityRange()` **不再重算**；`refreshCutTimelineAssets()` 里那句
  `rebuildCutWaveform()` 删掉；换文件与关窗都 `waveBuilder_.stop()`；
  `rebuildCutWaveform()` 降级为"全量失败时的兜底"（退回只算可见区间）。

**实测**

6 秒片（`test/fix720.mp4`）：

```
已载入 时长=00:00:06.000 缩略图=5/5 波形点=2400 波形段=16/16 关键帧=6
```

10 分钟片（`test/long.mp4`，验证可见区优先 —— 整片可见时中心在 5:00）：

```
波形段  8 00:05:00.000~00:05:37.500   1/16
波形段  7 00:04:22.500~00:05:00.000   2/16
波形段  9 00:05:37.500~00:06:15.000   3/16
波形段  6 00:03:45.000~00:04:22.500   4/16
波形段  5 00:03:07.500~00:03:45.000   5/16
波形段 11 00:06:52.500~00:07:30.000   6/16
…（从中心向两边扩散，最后才是 0 和 15）
波形段  1 00:00:37.500~00:01:15.000  16/16
```

完成顺序 **8→7→9→6→5→11→10→4→3→12→2→13→0→14→15→1**，正是"从可见区中心往外"，
证明优先级生效（不是从头到尾）。600s 片 240000 个峰值点，导入后 1 秒内 16 段全算完。
回归 `./scripts/regression.sh` **12/12**。

**两个实现中补上的细节**

1. `running_` 的收尾：最后一段算完才把"算中"状态清掉。
2. 段内也要响应 stop：一小时片子的一段就是好几分钟音频，换文件时若不能在段中间
   中断，`stop()` 的 `join()` 会把 GUI 线程卡住。现在 `sink` 里每次都查 stop 标志，
   且被打断的段**不标 ready**（不然会画出半截波形）。

## 7. 验收标准（开工后照这个测）

1. 导入 6s 片：波形**几乎立刻**可见（可见区那段先算完），日志显示分段完成情况；
2. 导入 1 小时片：画面先出来，波形**从左往右/从可见区往外**渐进填充，
   全程界面不卡（拖动标尺、缩放照常响应）；
3. 全量算完后**缩放、平移、播放、停止都不再触发波形重算**（看日志/CPU 占用确认）；
4. 播放中视窗滚动/翻页时波形跟随正常，无空洞误判；
5. 换文件：旧的全量任务立即停，不会把上一个文件的波形盖到新文件上；
6. `./scripts/regression.sh` 仍 12/12（波形不影响编码链路，但要确认没引入崩溃/挂死）。
