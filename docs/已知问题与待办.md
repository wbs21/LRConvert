## TODO-001　播放时的「页面滚动」改为「翻页」

- **状态**：✅ **已完成**（用户 2026-10-14 提出、同日开工并验证通过）
- **性质**：需求变更，不是 bug —— 原实现（滚动）是上一轮按用户要求做的，
  现在换成翻页

### 用户原话

> 播放时，放弃滚动模式，改为翻页，播放指针从左向右走，到达右端后，影片向左跳，
> 让当前帧回到最左端，相当于翻页。

### 现状（滚动模式，要被替换掉）

`TimelineWidget::centerViewOnCursor()`，播放线程每帧调一次：

```cpp
viewFrom = clamp(cursor - span/2, 0.0, duration - span)
```

即播放头**始终被摆在可见区中间**，影片连续向左滚；视窗顶到片头/片尾就钉住，
播放头自己往边上走（`src/ui/TimelineWidget.cpp` + `docs/Tab1_视频截取改版方案.md`
§4.1「播放时的页面滚动」那张三行表格）。

### 新行为（翻页模式）

1. 视窗**不动**，播放指针（蓝标尺）在可见区内**从左向右走**；
2. 指针走到可见区**右端**时，影片整体**向左跳一页**，
   指针随即出现在新页面的**最左端**；
3. 片尾不再有"钉住 + 播放头往右走"这一种，翻页到最后一页为止。

### 下次开工的实现草案（待用户确认后再写）

```cpp
// 替掉 centerViewOnCursor() 的连续滚动，改成"到边才翻"
if (cursor_ >= viewTo_ - eps) {          // 走到右端了
    const double s = std::min(span(), duration_);
    const double from = std::min(cursor_, duration_ - s);  // 新页左端 = 当前帧
    if (std::abs(from - viewFrom_) > 1e-6) {
        viewFrom_ = from;
        viewTo_   = from + s;
        clampView();
        update();
        emit viewChanged(viewFrom_, viewTo_);   // 别每帧都发，只在真翻页时发
    }
}
```

要点：

- **只在真正翻页的那一帧改视窗并 `update()`**，其余帧只动指针 —— 否则又变回滚动，
  而且每帧 `viewChanged` 会触发波形重算 + 5 张缩略图重取；
- 翻页后当前帧在**最左端**（`from = cursor`），不是居中、也不留余量；
- 片尾用 `duration_ - span()` 钳住，最后一页翻过去之后指针继续走到片尾才结束。

### 会牵动的地方（开工时一并改）

| 位置 | 要改什么 |
| --- | --- |
| `src/ui/TimelineWidget.cpp` `centerViewOnCursor()` | 换成上面的翻页逻辑（函数改名 `pageViewForCursor()` 更贴切） |
| `src/ui/TimelineWidget.h` | 声明同步改名 + 注释改掉 |
| `src/MainWindow.cpp` 播放帧回调 | 调用点改名（`timeline_->centerViewOnCursor()`） |
| `docs/Tab1_视频截取改版方案.md` §4.1 | 「播放时的页面滚动」整节 + 三行表格 + 冒烟数据换成翻页版 |
| `src/main.cpp` 冒烟 | 期望值要变：播到 2s 时**视窗仍是 0~2**（不是 1.1~3.1）；跨过右端后才翻到 2~4 |

### 落地结果（2026-10-14 已完成）

- `TimelineWidget::centerViewOnCursor()` → **`pageViewForCursor()`**，逻辑换成上面的翻页版；
- `MainWindow` 播放帧回调调用点同步改名；
- 冒烟加了「播放 1s（页内）」这一行做判据 —— 翻页模式下播了 1 秒视窗仍是 0~2 不动，
  滚动模式下此时已变成 0.45~2.45；
- 实测（6s 片，视窗 0~2）：

  ```
  播放 1s（页内）：            标尺=00:00:00.900  视窗=00:00:00.000~00:00:02.000  ← 不动
  播放 2.1s（已翻页）：        标尺=00:00:02.100  视窗=00:00:02.000~00:00:04.000  ← 整页左跳
  点击 4.9s 播 1s 后（末页）：  标尺=00:00:05.700  视窗=00:00:04.000~00:00:06.000  ← 钳片尾
  ```

  标尺 2.100 > 页左端 2.000，说明翻页后播放头确实落在新页最左端、再继续往右走。
- 方案文档 `docs/Tab1_视频截取改版方案.md` §4.1 已换成翻页版（含与滚动的分水岭对比表）。

  该文档 §8 有三步回滚步骤
- **完整方案草案**：`docs/音频波形_新方案_分段全量.md`（本条只做索引）

### 用户原话

> 新的音频波形绘制方法，我想改为：先导入视频，然后开始分 4 线程分段全量计算波形，
> 边计算边绘制。优先计算可见区域内的波形。

### 与现状的关键差别

| | 现状 | 新方案 |
| --- | --- | --- |
| 算多少 | 只算当前可见区间 | 整条音轨全量 |
| 何时算 | 导入算一次，**每次缩放/平移重算** | 导入算一次，**之后不再重算** |
| 线程 | 1 个后台任务 | **4 worker 分段并行** |
| 出图 | 整段算完才刷新 | **每算完一段就重绘** |
| 优先级 | 无 | **可见区所在段优先** |

### 开工前要拍板的数（草案里给了建议值）

| 项 | 建议 |
| --- | --- |
| 峰值密度 | **400 点/秒**（>2 小时的片子降到 100） |
| 分段粒度 | **16 段**（多于线程数，便于优先级调度） |
| worker | **4**（用户指定；机械硬盘上可能要降） |
| 内存 | 1 小时 ≈ 5.8MB，10 小时降档后 ≈ 14MB |

### 三个必须注意的实现点

1. **大数组先 `resize()` 到位、之后不改大小**，4 线程写互不重叠的下标区间
   （不同元素是不同内存对象，且不 realloc → 并发安全），这样也天然支持边算边画；
2. **每个 worker 各开一份文件句柄和解码器** —— `av_read_frame` 是"读走一个包"，
   共用 `AVFormatContext` 会互相偷包；
3. **空洞 ≠ 静音**：没算到的片画占位/留白，**不能画成 0 高度**，否则看着像静音。
   给峰值数据加"已完成水位线"，`peakLevel()` 遇到未完成区间返回一个"空洞"标记。

### 落地摘要（2026-10-14）

- 新增 `src/ffmpeg/WaveformBuilder.{h,cpp}`（16 段 / 4 worker / 优先级队列 / 可中断）；
  `AudioPeaks` 加 `allocate()` + `ready[]` + 把解码骨架抽成 `decodeRange()` 供三处复用；
  `TimelineWidget` 的 `peaks_` 改成 `shared_ptr<const>`（共享不拷贝）；
  `MainWindow` 新增 `startFullWaveform()`，`onCutViewChanged` 改为只重排优先级。
- **实测**：6s 片 `波形点=2400 波形段=16/16`；600s 片 `波形点=240000`，
  段完成顺序 8→7→9→6→…→15→1（从可见区中心往外，证明"可见区优先"生效）。
- 回归 12/12。旧方案仍是回滚备胎（`docs/音频波形计算方法_存档.md` §8 三步回滚）。
